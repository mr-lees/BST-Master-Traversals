Binary Search Trees: Traversals & Deletions

Master the required theoretical concepts for OCR (H446), AQA (7517), WJEC, and Pearson Edexcel specifications. Understand tree depth, traversal orders, stack behavior, recursion, and node deletion edge-cases.

1. Tree Traversals & Specification Applications

Root -> Left -> Right Pre-Order

Pre-Order Traversal

Visit the current node first, then recursively process the left subtree, followed by the right subtree.

Copying / Cloning Trees: Preserves structural hierarchy when re-inserting elements into a fresh tree.
Prefix Expressions (Polish Notation): Used in expression trees where operators precede operands (e.g. + A B).
Left -> Root -> Right In-Order

In-Order Traversal

Visit all nodes in the left subtree, then visit the root node, and finally traverse the right subtree.

Sorted Key Retrieval: In a valid BST, an in-order traversal guarantees visiting keys in strictly ascending numerical/alphabetical order.
Infix Expressions: Produces standard mathematical infix expression representation from binary expression trees.
Left -> Right -> Root Post-Order

Post-Order Traversal

Recursively visit left and right subtrees before visiting the parent root node.

Safe Tree Deletion / Deallocation: Children are freed before the parent node, avoiding dangling pointers in low-level memory management.
Postfix / RPN Evaluation: Generates Reverse Polish Notation (A B +) evaluated easily using stack architectures.

2. Deleting Nodes from a BST (3 Essential Cases)

Deleting a node from a Binary Search Tree requires maintaining the BST invariant: for every node, all left subtree values must be smaller, and all right subtree values must be greater.

1

Leaf Node (0 Children)

Action: Direct Removal.
Simply set the parent node's pointer (left or right) pointing to this target node to null or None.

2

Node with 1 Child

Action: Bypass Target Node.
Connect the target node's parent directly to the target node's single child subtree, bypassing the deleted node.

3

Node with 2 Children

Action: In-Order Successor Replacement.
Find the In-Order Successor (smallest value in the right subtree: go right once, then left as far as possible). Copy its value to the target, then recursively delete that successor leaf/single child.
